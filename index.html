Overview

Overview

This page demonstrates a sticky scroll-spy sidebar: as you scroll through the document, the navigation on the left automatically highlights the section currently in view, and clicking a link smooth-scrolls to that section. The active state is driven by a real IntersectionObserver, not a throttled scroll-position calculation.

Forge Studio builds product interfaces where motion and navigation explain structure rather than decorate it. A scroll-spy is a small example of that idea: the reader never loses their place in a long document.

Installation

Drop the three files (index.html, styles.css, spy.js) onto any static host. No build step, no dependencies, no framework.

The scroll-spy itself is about 40 lines of vanilla JavaScript. It observes every <section> that has a matching nav link and updates the .active class as sections cross a horizontal trigger line near the top of the viewport.

Configuration

The one tunable value is the observer's rootMargin, which sets where in the viewport a section counts as "active." Here it's biased toward the top third so the highlighted item matches what the reader is actually looking at.

A too-aggressive margin makes the active item flicker between neighbors; a too-loose one highlights a section before it's really on screen. The value below is a reasonable default for long-form docs.

Usage

Add a <section id="..."> for each chunk of content and a matching <a href="#..." data-target="..."> in the sidebar. The script wires everything up automatically on load — no per-section configuration.

Clicking a link uses native CSS scroll-behavior: smooth plus scroll-margin-top on each section so headings aren't hidden under the sticky header on jump.

Theming

All colors are CSS custom properties on :root. The active nav link, progress bar, and accent all derive from a single --accent variable.

Because the active state is a plain .active class toggle, you can style it however you like — a left border, a background pill, a bold weight — without touching the JavaScript.

API Reference

The script exposes nothing globally by design; it's a self-contained side effect. If you need programmatic control, the IntersectionObserver instance and the sections/links maps are easy to lift out into a module.

A common extension is to also update location.hash as the active section changes, so the URL reflects scroll position — deliberately left out here to avoid polluting browser history on every scroll.

FAQ

Why IntersectionObserver instead of a scroll listener? It's async, off the main thread, and doesn't require manual throttling — far smoother than recomputing offsets on every scroll event.

Does it work with a variable-height sticky header? Yes — adjust scroll-margin-top and the observer's top rootMargin to match the header height.
